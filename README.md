# ProxyHarvest

Proxy harvesting, truthful reachability/protocol verification, ranking, export, SplitNet/WireGuard tooling and bounded AI repair guidance.

## V38 runtime requirements

### Real verification bridge

`VERIFIED` is reserved for real protocol/tunnel evidence. Worker/browser reachability is never promoted to verified.

Run the local verifier on the machine whose network you want to test through:

```bash
npm run bridge
```

The bridge listens on `http://127.0.0.1:8787` and is auto-detected by the UI. For transport-only TCP/TLS checks, Node is sufficient. For real tunnel verification, install `sing-box` and `curl` so the bridge can launch the config locally and request `https://www.cloudflare.com/cdn-cgi/trace` through the resulting SOCKS tunnel. WireGuard verification uses sing-box WireGuard endpoint support when available.

### Hugging Face repair advisor

Set these in Vercel Environment Variables, never in the browser token fields:

- `HF_TOKEN` — Hugging Face token with Inference Providers permission
- `HF_MODEL` — optional; defaults to `Qwen/Qwen2.5-7B-Instruct-1M:fastest`

The API uses Hugging Face Inference Providers via `https://router.huggingface.co/v1/chat/completions`. Model output can only select bounded candidate IDs already generated by deterministic repair rules. A repair is never treated as verification.

### Infrastructure defaults

The app automatically uses the configured ProxyHarvest Worker for fetch/reachability fallback. Clean IP, Reality public key and custom SNI are intentionally not fabricated: these values are endpoint/server specific. Use **SMART DEFAULTS + HEALTH CHECK** in Infrastructure to apply safe defaults and test Worker, Bridge and HF health.

### Exports

- **BEST VERIFIED**: only fresh protocol/tunnel-verified configs, ranked by score then latency.
- **BEST REACHABLE**: fresh high-score, low-latency endpoint-reachable candidates. These are explicitly not tunnel-verified.
